## 5. Do not fabricate model support

The existing model is based on the UCI Student Performance dataset, which contains Mathematics and Portuguese data. Removing Portuguese is a UI and code change; it does not automatically create valid models for all KV subjects.

For every class-subject combination, explicitly track whether a trained and evaluated model is available.

- Use a subject-specific model only when suitable training data and evaluation results exist.
- Do not apply the Mathematics model to Science, Hindi, Physics, Accountancy, or other subjects as though it were trained for them.
- Do not use synthetic records as real training or evaluation data.
- If a model is unavailable, display a clear message explaining that predictions for that subject are not yet supported.
- Provide a clean architecture for adding datasets and separately trained models later.

Keep model-evidence metrics tied to the correct dataset and subject. Never display old Mathematics metrics as evidence for another subject.
